# phase2-data-contracts Specification

## Purpose

为第二阶段算法引擎（S2 起的基准、可解释模型与非线性模型比较）提供可复建的数据、特征与验证合同：固定数据来源与清洗口径、明确特征边界与时间切分、预注册独立测试接收规则，并以可重复运行的检查保证相同输入重建相同样本与特征、开发与检验材料事件隔离。

## Requirements

### Requirement: 来源指针与数据哈希固定

第二阶段数据层构建训练主表时，SHALL 在构建开始时解析一次用户自备数据来源指针，将实际数据 run 标识与文件哈希固定并写入 run 清单；构建过程与后续重建 SHALL 使用该固定指针，不得在途中自动读取可能变化的当前指针（如 `current.json`）。

#### Scenario: 构建时固定指针与哈希

- **WHEN** 构建训练主表的 run 启动
- **THEN** run 清单记录实际数据 run 标识、文件哈希与解析时间，主表仅由该固定数据构建

#### Scenario: 指针后续变化不扩散

- **WHEN** 来源指针文件在 run 构建完成后发生变化
- **THEN** 已建 run 与其产物不受影响，重建仍使用 run 清单中固定的数据 run 与哈希

### Requirement: 训练主表与清洗合同

数据层 SHALL 以一行一个成交事件为粒度构建训练主表，每行保留来源记录 ID、小区 ID、成交日期、总价、面积、原值与解析值、质量状态和来源血缘字段。清洗 SHALL 按 S0 修正口径的规则集（来源记录 ID 去重、跨 ID 疑似同套裁决、价格与面积区间过滤、单价区间过滤）执行，清洗后行数 SHALL 与 S0 修正链登记值对账一致；每次构建 SHALL 落盘排除清单，逐条登记各步行数、剔除原因与裁决明细。

#### Scenario: 主表对账一致

- **WHEN** 按合同构建训练主表
- **THEN** 清洗后行数与 S0 修正链登记的 27,964 对账一致，不一致时构建流程报告差异并停止

#### Scenario: 排除清单可追溯

- **WHEN** 任一行在清洗中被剔除
- **THEN** 排除清单可定位该行被哪条规则剔除及当时的关键字段值

### Requirement: 记录 ID 语义与去重边界

数据层 SHALL 登记来源记录 ID 的语义（房源标识、挂牌标识或成交事件标识）及判断依据。去重 SHALL 仅合并确认为同一交易的重复记录；同一套房的真实不同次成交 SHALL 按成交时间顺序全部保留；不得因属性相近自动删除不同交易。

#### Scenario: 疑似同套裁决留痕

- **WHEN** 两条记录被判为疑似同一交易并去重
- **THEN** 裁决明细（保留与剔除的记录 ID、判断依据）写入排除清单，供人工复核

#### Scenario: 同房源多次成交保留

- **WHEN** 同一房源存在日期不同、非重复导出的多次真实成交
- **THEN** 两条记录均保留在主表中且成交时间顺序可查

### Requirement: 特征字典完备性与标签边界

特征字典 SHALL 覆盖位置、产品、建筑、房屋、市场、质量与支持度六组特征，每个字段 SHALL 至少写明：原字段、计算方式、粒度、可用时点、缺失与异常处理、是否使用成交标签、训练与预测时能否同时获得。成交总价及由其直接推导的单价 SHALL 仅作标签；目标成交之后才产生的信息、未来回填属性、挂牌价 SHALL NOT 进入历史预测输入。装修、电梯等可变化属性在无法证明为历史状态时，SHALL 登记纳入与排除的敏感性实验安排，不得宣称已满足严格历史可得性。建筑年份与总层数字段 SHALL 附带近期覆盖率与监控规则（承接数据门条件 2）。

#### Scenario: 字典字段元信息齐全

- **WHEN** 检查特征字典任一字段条目
- **THEN** 七项元信息（原字段、计算方式、粒度、可用时点、缺失与异常处理、标签使用、训练与预测可得性）全部写明

#### Scenario: 标签衍生禁入特征

- **WHEN** 生成任一历史时点的预测输入特征
- **THEN** 该输入不包含目标成交总价、由其直接推导的单价、目标成交后信息与未来回填属性

#### Scenario: 覆盖监控规则登记

- **WHEN** 特征字典定稿
- **THEN** 建筑年份与总层数字段附有近期覆盖率基线与后续批次到达时的监控规则

#### Scenario: 附加字段解析特征纳入

- **WHEN** 特征字典定稿
- **THEN** 梯户比例（梯数、户数、比值，建筑组）、板块（来源片区，位置组）、产权共有状态、满二满五税费状态、房屋权属标记（后三者属房屋组权属与税费子类）作为第一版特征登记，来源标注为来源附加字段；"房屋年龄"键的键名与语义分歧（实为满二满五税费口径）在字典显式登记；解析失败或缺失保留未知，覆盖率与解析成功率随字典登记

#### Scenario: 主表扩展特征纳入

- **WHEN** 特征字典定稿
- **THEN** 房屋类型（塔楼/板楼/板塔结合/平房/未知）与建筑面积及派生得房率作为第一版特征登记（建筑组/产品组），来源为主表列；建筑面积覆盖率（约 44%）随字典登记，缺失保留未知

### Requirement: 时间切分与用途切片

切分合同 SHALL 登记已用于开发评估的窗口 A（2026-01-01～2026-07-20）与 B（2025-07-21～2025-12-31）为已观察开发证据，并披露其曾被 DATA2 实验与本校正观察的事实；SHALL 按时间分布形成滚动开发折，并为训练、调参与区间校准预分互不重叠的用途切片；每折的预处理、时间指数、市场聚合与类别编码 SHALL 仅在该折训练材料中拟合。

#### Scenario: 已用窗口披露

- **WHEN** 切分清单生成
- **THEN** A、B 窗口标注为已观察开发证据，不出现将其改称独立测试的表述

#### Scenario: 折内拟合边界

- **WHEN** 任一开发折内生成类别编码或市场聚合
- **THEN** 其拟合材料仅来自该折训练切片，不含该折验证切片数据

#### Scenario: 用途切片互不重叠

- **WHEN** 训练、调参与区间校准切片生成
- **THEN** 任意两个用途切片不共享成交事件，重叠时检查报告为失败

### Requirement: 信息截点与泄漏边界

开发验证 SHALL 采用固定信息截点：验证或测试窗口内的成交价 SHALL NOT 加入该窗口预测的市场特征；按天披露的数据 SHALL NOT 互用同一天未知先后顺序的成交；训练行的价格聚合与价差基准 SHALL 仅使用严格早于该行的证据并排除自身交易。

#### Scenario: 截点后价格不入特征

- **WHEN** 为验证窗某成交生成市场特征
- **THEN** 特征计算不含该成交及信息截点之后任何成交的价格

#### Scenario: 自身交易排除

- **WHEN** 为训练主表某行计算其市场聚合特征
- **THEN** 聚合证据排除该行自身，且全部证据的成交时间严格早于该行

### Requirement: 最终测试接收规则预注册

开发验证合同 SHALL 预注册最终独立测试的接收规则：只接收信息截点（2026-07-20）之后产生且此前从未用于任何分析的新成交，按预定日期窗口与资格规则登记，不得依据表现挑选样本；已被观察过的材料 SHALL NOT 重新命名为独立测试（承接数据门条件 3）。

#### Scenario: 接收规则冻结

- **WHEN** 开发验证合同定稿
- **THEN** 最终测试的接收窗口、资格规则与排除规则已写入合同，且此后不因候选表现修改

#### Scenario: 已观察材料不转正

- **WHEN** 任何曾进入开发分析的材料被提议用于最终测试
- **THEN** 接收检查拒绝该材料并登记拒绝原因

### Requirement: 下一批更新接收规则

数据层 SHALL 登记下一批用户自备数据到达时的核对规则（新增、重复、修订与取得时间的检查项）并保留旧快照；更新未到达时 SHALL 登记为未验证状态，不阻塞开发数据准备（承接数据门条件 1 的规则部分，实测待新批次到达）。

#### Scenario: 更新未到登记未验证

- **WHEN** 构建时下一批更新尚未到达
- **THEN** 运行清单登记该项为未验证及核对规则，开发数据准备不受阻塞

#### Scenario: 旧快照保留

- **WHEN** 未来新批次数据进入
- **THEN** 本轮固定快照及其哈希保持不变，供对账与回溯

### Requirement: 评估身份映射

合同 SHALL 为算法比较与实际系统比较的共同目标建立可核验的评估身份映射（用户自备数据侧小区 ID 与现行引擎实体的对应），SHALL 记录未匹配数量与原因；该映射 SHALL 仅服务评估与请求边界，SHALL NOT 改变数据侧训练 ID 体系。现行引擎无法按合同重建的历史输入 SHALL 披露为缺失，不得编造对应估值。

#### Scenario: 映射建立与未匹配登记

- **WHEN** 生成评估身份映射
- **THEN** 映射表记录每侧标识、匹配状态与未匹配数，未匹配原因可归类

#### Scenario: 映射不反向改训练 ID

- **WHEN** 映射中存在一对多或不确定对应
- **THEN** 外部训练主表的 ID 与行不因此被合并或改写

### Requirement: 泄漏、隔离与重建检查

数据层 SHALL 提供可重复运行的检查：标签与未来信息泄漏检查、训练/验证/最终测试事件隔离检查、相同输入重建一致性检查（相同源数据与合同重建出相同主表、切分与特征）。检查 SHALL 以未编辑输出留证，检查失败时 SHALL 报告失败而非静默通过。

#### Scenario: 重建一致

- **WHEN** 用相同源数据与同一合同指纹重建主表、切分与特征
- **THEN** 两次产物逐行一致，检查输出为通过

#### Scenario: 事件隔离

- **WHEN** 检查训练、验证与最终测试三个集合
- **THEN** 同一成交事件不出现在一个以上集合，出现时检查报告为失败

#### Scenario: 泄漏检查拦截

- **WHEN** 构造含截点后信息或标签衍生的特征输入并运行泄漏检查
- **THEN** 检查报告为失败并定位违规字段

### Requirement: 运行清单与合同冻结

每次数据层构建 SHALL 产出运行清单，绑定源数据 run 与哈希、代码版本与未提交改动指纹、合同指纹、切分清单与排除清单。开发验证合同文档 SHALL 随 run 落盘，至少包含：预测目标、适用范围、原始快照、清洗规则、时间切分、模型角色（B0/B1/M1–M4 对照框架）、指标定义、数据泄漏检查项、试验预算占位与比较人群定义。

#### Scenario: run 自描述可追溯

- **WHEN** 查看任一数据层 run 目录
- **THEN** 无需外部上下文即可确定其源数据、代码版本、合同与切分来源

#### Scenario: 合同文档完整

- **WHEN** 审阅开发验证合同文档
- **THEN** 九项内容（目标、范围、快照、清洗、切分、模型角色、指标、泄漏检查、比较人群与预算占位）全部成文
